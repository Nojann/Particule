# API reference

All routes are served under `/api/v1`. The interactive OpenAPI docs, generated by FastAPI from the code, are at http://localhost:8000/docs (Swagger) and http://localhost:8000/redoc. This page explains the conventions behind them.

## Conventions

### Authentication

Get a token, then send it on every request:

```bash
curl -X POST http://localhost:8000/api/v1/login/access-token \
  -d "username=alice@example.com" -d "password=secret-password"
# {"access_token": "eyJ...", "token_type": "bearer"}

curl http://localhost:8000/api/v1/users/me -H "Authorization: Bearer eyJ..."
```

The login body is a form (`application/x-www-form-urlencoded`), not JSON, as OAuth2 requires; the email goes in `username`. Tokens are valid for `ACCESS_TOKEN_EXPIRE_MINUTES` (2 days by default).

Every route needs a token except `POST /login/access-token` and `POST /users/signup`.

### Ownership

Knowledge bases, tags, links and sources belong to a user. Particules belong to a knowledge base, so to its owner. A user only ever sees their own resources: another user's resource answers **404**, exactly like an id that doesn't exist, so its existence is never revealed.

The owner always comes from the token and the knowledge base from the URL. `owner_id`, `knowledge_base_id` and `id` sent in a request body are ignored.

### Status codes

| Code  | Meaning                                                              |
| ----- | -------------------------------------------------------------------- |
| `200` | OK                                                                   |
| `201` | Created, the body is the new resource                                |
| `204` | Deleted, empty body                                                  |
| `400` | Request refused by a business rule (wrong password, inactive user…)  |
| `401` | Missing token                                                        |
| `403` | Invalid token, or not enough privileges (superuser routes)           |
| `404` | Not found, or not yours                                              |
| `409` | Conflict with an existing resource (duplicate email, tag, permalink…) |
| `422` | Invalid body, query or path parameter (e.g. malformed UUID)          |

Errors have the FastAPI shape: `{"detail": "Knowledge base not found"}`. For `422`, `detail` is a list describing each invalid field.

### Pagination

List routes take `skip` (default `0`) and `limit` (default `100`) query parameters:

```
GET /api/v1/tags/?skip=20&limit=10
```

### Updates

`PATCH` is a partial update: only the fields sent are changed.

## Login

| Method | Path                  | Description                                    |
| ------ | --------------------- | ---------------------------------------------- |
| `POST` | `/login/access-token` | Exchange email and password for a token        |
| `POST` | `/login/test-token`   | Return the user the token belongs to           |

`POST /login/access-token` answers `400` for a wrong email or password, and for an inactive user.

## Users

| Method   | Path                 | Access    | Description                          |
| -------- | -------------------- | --------- | ------------------------------------ |
| `POST`   | `/users/signup`      | public    | Create an account                    |
| `GET`    | `/users/me`          | user      | Read your own user                   |
| `PATCH`  | `/users/me`          | user      | Update your `full_name` or `email`   |
| `PATCH`  | `/users/me/password` | user      | Change your password                 |
| `DELETE` | `/users/me`          | user      | Delete your account and all its data |
| `GET`    | `/users/{user_id}`   | user      | Read a user (yourself, or any user as superuser) |
| `GET`    | `/users/`            | superuser | List users, with `count`             |
| `POST`   | `/users/`            | superuser | Create a user                        |
| `PATCH`  | `/users/{user_id}`   | superuser | Update a user                        |
| `DELETE` | `/users/{user_id}`   | superuser | Delete a user                        |

User responses never contain the password or its hash:

```json
{
  "id": "6f1c…",
  "email": "alice@example.com",
  "full_name": "Alice",
  "is_active": true,
  "is_superuser": false,
  "created_at": "2026-10-21T08:30:00"
}
```

`GET /users/` wraps the list: `{"data": [...], "count": 42}`, where `count` is the total number of users, not the page size.

Rules:

- Signup: `email`, `password` (8 to 128 characters), optional `full_name`. An email already used answers `400`.
- Changing your email, or a user's email as superuser, to one already used answers `409`.
- `PATCH /users/me/password` takes `current_password` and `new_password`; a wrong current password, or a new password equal to the current one, answers `400`.
- A superuser can't delete themselves (`403`).
- Deleting a user deletes their knowledge bases, particules, tags, links and sources.

## Knowledge bases

| Method   | Path                      | Description                  |
| -------- | ------------------------- | ---------------------------- |
| `GET`    | `/knowledge-bases/`       | List your knowledge bases    |
| `POST`   | `/knowledge-bases/`       | Create a knowledge base      |
| `GET`    | `/knowledge-bases/{kb_id}` | Read a knowledge base       |
| `PATCH`  | `/knowledge-bases/{kb_id}` | Rename a knowledge base     |
| `DELETE` | `/knowledge-bases/{kb_id}` | Delete it and its particules |

Body: `{"name": "Physics"}`, with `name` up to 255 characters.

```json
{
  "id": "0b3e…",
  "name": "Physics",
  "owner_id": "6f1c…",
  "created_at": "2026-10-21T08:30:00",
  "updated_at": "2026-10-21T08:30:00"
}
```

`updated_at` is set on creation and refreshed by every `PATCH`.

## Particules

Particules live in a knowledge base, and every route goes through it:

| Method   | Path                                                       | Description                   |
| -------- | ---------------------------------------------------------- | ----------------------------- |
| `GET`    | `/knowledge-bases/{kb_id}/particules/`                     | List the particules, by title |
| `POST`   | `/knowledge-bases/{kb_id}/particules/`                     | Create a particule            |
| `GET`    | `/knowledge-bases/{kb_id}/particules/{particule_id}`       | Read a particule              |
| `GET`    | `/knowledge-bases/{kb_id}/particules/by-permalink/{permalink}` | Read a particule by permalink |
| `PATCH`  | `/knowledge-bases/{kb_id}/particules/{particule_id}`       | Update a particule            |
| `DELETE` | `/knowledge-bases/{kb_id}/particules/{particule_id}`       | Delete a particule            |

A knowledge base that isn't yours answers `404` on every route, and so does a particule that isn't in the knowledge base of the URL, even one of yours.

Create body (`source_id` is optional):

```json
{
  "title": "Entropy",
  "permalink": "entropy",
  "content": "A measure of disorder.",
  "origins": "Thermodynamics course",
  "source_id": "a91d…"
}
```

The response adds `id` and `knowledge_base_id`. A particule can't be moved to another knowledge base.

Permalinks are unique **across all knowledge bases and users**: a permalink already used anywhere answers `409`, on creation and on update.

## Tags

| Method   | Path              | Description              |
| -------- | ----------------- | ------------------------ |
| `GET`    | `/tags/`          | List your tags, by name  |
| `POST`   | `/tags/`          | Create a tag             |
| `GET`    | `/tags/{tag_id}`  | Read a tag               |
| `PATCH`  | `/tags/{tag_id}`  | Rename a tag             |
| `DELETE` | `/tags/{tag_id}`  | Delete a tag             |

Body: `{"tag": "physics"}`, from 1 to 255 characters. Response: `{"id": "…", "tag": "physics", "owner_id": "…"}`.

A user can't have the same tag twice (`409`), but two users can each have it.

## Links

| Method   | Path                | Description              |
| -------- | ------------------- | ------------------------ |
| `GET`    | `/links/`           | List your links, by URL  |
| `POST`   | `/links/`           | Create a link            |
| `GET`    | `/links/{link_id}`  | Read a link              |
| `PATCH`  | `/links/{link_id}`  | Change a link's URL      |
| `DELETE` | `/links/{link_id}`  | Delete a link            |

Body: `{"link": "https://arxiv.org/abs/1234.5678"}`, not empty. Response: `{"id": "…", "link": "…", "owner_id": "…"}`.

A user can't have the same link twice (`409`), but two users can each have it.

## Sources

| Method   | Path                    | Description                          |
| -------- | ----------------------- | ------------------------------------ |
| `GET`    | `/sources/`             | List your sources, by authors then year |
| `POST`   | `/sources/`             | Create a source                      |
| `GET`    | `/sources/{source_id}`  | Read a source                        |
| `PATCH`  | `/sources/{source_id}`  | Update a source                      |
| `DELETE` | `/sources/{source_id}`  | Delete a source                      |

Body (all fields required on creation):

```json
{
  "authors": "Richard Feynman",
  "year": 1964,
  "edition": "1st",
  "publisher": "Addison-Wesley"
}
```

The response adds `id` and `owner_id`. Unlike tags and links, the same source can be created twice.

Deleting a source keeps the particules that cite it: their `source_id` becomes `null`.
